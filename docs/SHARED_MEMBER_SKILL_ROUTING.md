# Shared member skill learning route

Step 4 local implementation; no release admission claimed.
Brain validates the same trusted bound scope and existing task evidence as before.
An optional `portability` object declares exactly boolean `reusable`,
`contains_workspace_data`, `contains_credentials`, and `has_workspace_dependencies`.
Credentials are refused. Declarations are explicit semantic evidence, not inferred
from source ownership or task success; Brain forwards them unchanged to Skills.

Skills owns proposal evaluation, approval, package security, actual shared/private
placement, revisions and rollback. Explicit workspace-only intent cannot be widened
by portable method. Missing portability is not shared admission. The configured
member route uses the same library lifecycle as ordinary imports; unconfigured
legacy owners remain compatible. Runtime configuration and Connection permissions
stay with OS. No strategy/authority/permission transfer is introduced.
